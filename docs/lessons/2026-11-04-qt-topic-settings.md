# UKE-QT-TOPICS-20261104: present daily settings as grouped topics

Date: 4 November 2026. Initial environment: Fedora Rawhide aarch64 on POCO Pad X1,
Qt 1.1.0-2, Control/client 2.8.1-23, running kernel 7.3.1-7200-unstable.

The approved settings plan replaces command-shaped daily guides with six daily
categories and secondary Help/Advanced. Topic pages combine bounded passive
reads, semantic information rows and in-page preference editing. The complete
SDK catalog remains an expert fallback. Original KDE settings links are fixed,
discovered distribution modules; simulation/read-only sessions cannot launch them.

Typed Query reads remain read-only, serialized and cancellable. Existing frozen
reviews, authorization, exact confirmations and terminal writers remain in the
shared frontend path. Terminal launch is not reported as successful application.
Charging preferences remain unavailable when the provider has not admitted them.
No immediate switches or arbitrary command execution are added.

Radio choices represent real flashlight levels and small choice sets. File,
folder, colour and discovered device selection use native controls. Draft values
have a separate notification so typing does not rebuild and defocus the form.
Turkish translations cover the new daily topic interface.

UPower history uses bounded asynchronous read-only discovery of the actual
power-supply battery, rather than a hardcoded object or the composite display
device. Unknown states, duplicate timestamps and long gaps break the plotted
line. A small native Qt painted chart uses actual timestamps and the current
palette; it avoids resampling gaps into false zero values. No recording daemon,
history store, charging operation or kernel/slot write is added. Original KDE
packages are not forked. Build and tablet results remain pending.

New tests exercise zero/negative/unknown measurements, unsupported qualification,
history ordering and discontinuities, cancellation, real discrete choices and
every topic in the real QML scene. Fixture history cannot contact the system bus.
Opt-in installed checks additionally request existing UPower history. Native
compilation and RPM testing take place in COPR; device installation uses DNF.
