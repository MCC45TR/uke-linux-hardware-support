# Keep OEM update inputs independent of Android super

On17 November2026, a fresh POCO Pad X1 root runs the accepted full4 kernel
with super assigned to swap/rescue. The existing Control26 trigger refuses
full5 staging because its required private-color acquisition still reads ODM.
The later video import uses that same missing source.

The factory-input reader uses the existing protected descriptor helper and
the existing complete-file validators. Public OEM supplier JSON and an older
public video revision match all three already admitted hashes. The firmware
package owns their immutable source paths; no hash, ELF, fitted supplier or
private-v5 admission is expanded. Existing source errors fail with unchanged
output. Missing files retain the original read-only ODM fallback for existing
installations. Board and candidate checks, private0600 profile publication,
versioned video publication, signed RPM checks and inactive-slot rollback stay
in their existing paths. No service, runtime ELF or hardware protocol is added.

The candidate qualifies the actual protected reader in both complete native
applications with GCC and Clang, plain and ASan/UBSan. Cases cover missing and
valid sources, wrong owner/mode/ancestor, hardlinks, live/dangling symlinks,
directories, altered/truncated contents, rejected/throwing admission and
unchanged output. Native tests do not execute firmware or access a tablet.

The gray-screen runtime fix remains the separately built MDP no-init-park
change. Factory-source availability makes its guarded delivery possible; it
does not establish optical success. That requires a verified inactive slot,
normal reboot, bounded webcam recording and actual native health acceptance.
